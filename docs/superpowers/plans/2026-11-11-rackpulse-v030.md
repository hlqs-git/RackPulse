# RackPulse v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 兼容历史数据地修复事件时间，并交付一致的CLI/飞书卡片报告与安全投递。
**Architecture:** JSON只读适配层→统一ReportView→text/cards双渲染；事件生产修复与展示隔离；卡片投递使用新增表，旧记录不变。
**Tech Stack:** 沿用Python3.12/FastAPI/SQLAlchemy/PostgreSQL/httpx/APScheduler/K3s/GHCR。
**Spec:** docs/v0.3.0/design.md；迁移、测试和运维规范见同目录其余文档。

## Global Constraints

- 不连接/修改生产，不删除数据，不批量重采/重算历史；映射与指标不变。
- Asia/Shanghai；day_duration_minutes≤1440；累计字段与旧duration_minutes兼容。
- 部分PSU/GPU代理不称机柜总能耗；缺失保留null；设备健康无证据为unknown。
- 旧镜像回滚前使用新镜像逻辑降级Alembic至0001，不删表。

## Review Focus

- 历史时间不足不能伪造当天持续（任务1）。
- 查询失败不能制造恢复或全天故障（任务2）。
- 飞书Critical/32柜不能因长度丢失（任务4）。
- 不确定投递不能自动重复（任务5）。
- 镜像回滚必须实际识别迁移版本（任务7）。
