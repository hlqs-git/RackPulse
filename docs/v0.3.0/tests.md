# v0.3.0 测试用例与验收矩阵

所有期望值手工推导，mock仅位于HTTP边界。真实历史输入与合成数据分目录标识，脱敏保留时间、标签、数值与关联关系。

| 层次/用例 | 输入与断言 |
|---|---|
| 跨日完整故障 | 11-09全天+11-10全天：各日day=1440，累计分别1440/2880，首次发生不变，恢复null |
| 午夜前后阈值 | 11-09 23:55至11-10 00:05：第二天day=5、total=10，恢复为+08:00的00:05 |
| 午夜即恢复 | 前日开放事件，当日00:00有效恢复：day=0、total保留 |
| 未知区间 | 查询失败不制造恢复，也不能把未知分钟加入已证实累计 |
| 单次查询失败 | 有实际请求时间、历史受影响窗口、最终失败类别；故障持续null，绝不默认全天1440 |
| 重试后成功 | 不生成持续Critical故障；保留执行诊断 |
| 四类状态 | 执行完成但部分查询失败≠任务运行失败≠设备硬件故障；设备健康默认unknown |
| 历史适配 | 旧2880分钟与旧错误datasource_error只读适配；无法推导day时为unknown；原JSON字节/内容不变 |
| 设备事件追溯 | 汇总前后原始事件数量、身份、时间、等级一致，通知只使用归并副本 |
| 卡片覆盖 | 配置32柜全部出现且仅出现一次；POD各16柜；异常优先，缺柜占位；Critical溢出附卡不丢失 |
| 能耗 | 三来源分别积分/展示；minutes=0时显示—；有效零值保留；不混合来源/缺失补零 |
| 昨日变化 | 同品牌同集合全天覆盖才比较，展示可比柜数；不具备条件为— |
| 趋势 | 7/30日期槽含缺日null；覆盖率与可比范围明确；不外推缺失能耗 |
| 排名 | GPU与完整PSU覆盖≥95%、利用率<10%；同来源按功率降序；部分PSU排除 |
| CLI一致性 | text与cards与send共用ReportView；cards导出JSON与MockTransport实际请求内容一致（签名时间除外）；raw保持原数据 |
| 卡片幂等 | 并发领取仅一发送；重试失败第二卡不重发第一卡；unknown禁止自动重试；force新审计批次 |
| 长度 | 最终UTF-8 JSON限长，中文/特殊字符/超长行不破坏卡片，不丢任何机柜 |
| 崩溃恢复 | sending→unknown；确认未发送pending可继续，attempt记录不丢 |
| PG迁移 | 独立PostgreSQL导入0.2结构和两日数据→升0002→逻辑降级→0.2可启动→再升级；报告/映射/投递数据无损 |
| 发布 | Python3.12全测试、构建镜像、检查版本与registry digest；生产无操作 |

历史回归输入：2026-11-09、2026-11-10日报raw JSON；若需要精确追溯查询失败，附原任务记录/日志。当前尚未提供，必须将“真实历史回归未执行”单列，不能以相同日期合成夹具冒充。

追加回归：用真实v0.2 report.py渲染包含查询失败和新增时间字段的v3日报，断言不崩溃；用v0.3渲染相同数据断言故障持续为未知，不展示兼容占位0为实测值。
