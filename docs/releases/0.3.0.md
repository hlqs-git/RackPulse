# RackPulse 0.3.0

## 变更

- 新事件独立记录首次时间、当天时长、累计时长及已证实恢复时间；展示统一Asia/Shanghai。旧duration_minutes保留累计语义，新增字段不会重写历史。
- 查询失败保存实际请求观察时间、影响的历史窗口和指标；未知故障时长不再写成全天1440分钟。失败窗口不能作为设备恢复证据。
- 飞书interactive主卡片与POD1/POD2机柜明细，异常优先；超长按完整机柜/事件拆卡，Critical续卡不丢失。
- report --format text/cards/raw；预览和发送共用新模型，raw导出原始日报。
- 7/30日趋势和低利用率高功耗排名，缺日null，三种能耗来源分别显示。缺少历史时不伪造曲线。
- 0002仅新增卡片与尝试记录，原报告/配置不迁移、不删除。卡片独立幂等，失败卡可重新发送，已成功卡不重发；unknown需人工核实。

## 兼容与限制

没有重新采集或重算历史。旧事件无法可靠还原当天时长时显示—。旧查询错误1440分钟不作为全天故障证据。回滚至0.2前必须使用0.3执行逻辑降级，详见docs/v0.3.0/upgrade-rollback.md。

真实2026-11-09/10日报快照尚未提供，目前同日期回归使用明确标记的合成输入，不能视为现场数据验收。没有发送真实飞书或操作生产K3s。

卡片使用自定义机器人interactive协议，默认18KB拆卡阈值，并在签名后检查20KB请求体上限。协议依据：[飞书自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。
