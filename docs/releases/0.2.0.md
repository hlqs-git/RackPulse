# 0.2.0：精简飞书日报

- 全局概览、每柜一行汇总和最多10行重点事件。详细事件仍保存在日报结构化JSON，不修改采集、分析、数据库或映射。
- 通知层对相同起止区间的GPU缺采按节点归并，多节点进一步按机柜归并；不同区间不盲目合并。不能识别节点的设备保留原事件。
- 默认缺采连续5分钟才进入重点事件；短缺采计入数据质量。Critical不按时长过滤，优先展示。超过10条时第10行汇总所有剩余事件和Critical数量，详情仍可查询数据库。
- 功率显示kW，能耗显示MWh；无有效功率数据不输出来源字段，全部缺失时为“—”。有效零值仍按零展示。
- 状态区分监控数据异常与指标波动；没有直接设备健康指标时不判定硬件故障。高负载不进入重点告警。
- 发送历史日报时从已存储汇总重新渲染精简视图，无需重采；正文变化后内容哈希不同，显式手动发送会作为新内容投递。
- 按UTF-8字节长度和完整行分段。32柜、10条事件通常可合并为一条飞书文本；实际屏数取决于手机字体与显示宽度，无法保证固定1–3屏。

镜像由GitHub Actions在版本标签推送后测试、构建并上传 `ghcr.io/hlqs-git/rackpulse:0.2.0`。首次发布的包可能为私有，需在GitHub包设置确认可见性，或为K8s配置imagePullSecret。

K8s升级时在kustomization.yaml配置：

```yaml
images:
  - name: rackpulse
    newName: ghcr.io/hlqs-git/rackpulse
    newTag: 0.2.0
```

若原来已有images段，替换该项，不重复添加。然后重新apply，迁移及应用容器会使用同一版本：

```sh
git pull --ff-only
kubectl apply -k deploy/k8s
kubectl -n rackpulse rollout status deployment/rackpulse --timeout=300s
```

没有结构化summaries的旧记录仍沿用旧正文，不保证自动精简。
