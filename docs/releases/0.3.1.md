# 0.3.1：GPU / PSU 监控数量概览

默认飞书日报只展示：GPU与PSU分别统计的应监控、实际采集、监控正常、监控降级、监控不可用，以及全部机柜的GPU应/实、PSU应/实和数量/采样状态。异常机柜优先，无能耗、趋势、排名及逐设备事件通知；这些原始统计和详细事件仍保存在数据库。

32柜默认应监控2304张GPU、1536路PSU；使用配置中的实际expected_gpu/expected_psu，不在渲染器硬编码总数。正常/降级按单设备有效采样分钟/1440是否达到95%分类，GPU以利用率指标、PSU以输入功率指标统计。实际采集为当天至少一次有效采样的去重设备数。

新日报增加monitoring_counts JSON，不新增数据库表，不修改机柜映射或查询指标。查询失败时不可用数量为未知；历史报告没有设备级分类统计时对应值显示—，不能从平均完整率推算。缺失机柜日报不直接断言全部设备不可用。实际数量超过预期时标记超配并避免计算负数不可用。采集状态不等于硬件健康，健康显示未判定。

CLI text/cards与实际推送继续共用渲染器，raw仍原样导出历史数据。原0.3.0卡片投递记录不删除；内容变化后显式send会作为新批次投递，不自动重发历史日报。

升级镜像（无需改数据库、配置或重采历史）：

```sh
kubectl -n rackpulse set image deployment/rackpulse app=ghcr.io/hlqs-git/rackpulse:0.3.1 migrate=ghcr.io/hlqs-git/rackpulse:0.3.1
kubectl -n rackpulse rollout status deployment/rackpulse --timeout=300s
```

生产环境由用户执行，开发会话不访问生产。新生成日报才能提供准确的单设备分类；旧日报仍可预览数量汇总和明确的未知分类。
